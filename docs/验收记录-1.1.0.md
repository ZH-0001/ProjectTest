## 场景覆盖

- 原41项：时间、预约与取消边界、事务回滚、座位和同用户并发冲突、幂等、管理操作竞态、权限、CSRF、历史快照、推荐与统计。
- 新规则：SET/CLEAR批次原子校验、保留其他字段、布尔false、显式偏好只覆盖对应维度、HARD过滤先于top5、无历史来源、滚动分钟和北京时间日限额、额度并发、预算、缓存和卡片时效边界。
- 对话：相同UUID在途复用及成功／失败重放、同UUID不同消息冲突、同会话忙碌、全局5任务、模型与工具上限、超时、失败草稿丢弃、重置及失效会话的迟到回复、20轮完整工具链裁剪、重复工具调用ID及空回复。
- 模型适配：实际HTTP顶层thinking关闭、三个工具定义、续传工具结果；401／429／500响应脱敏且不隐藏重试；读取超时使用剩余预算；关闭开关或无密钥不创建模型。
- 真实数据库与助手HTTP：学生角色、未登录、CSRF、额外身份字段拒绝、白名单外工具拒绝、本人预约、跨Session卡片不可访问、首次预约过期、成功后超过2分钟及取消后的原结果重放、座位被抢后的重新校验。
- 真实DeepSeek：搜索自习室和座位、仅修改开始时间并保留其余偏好、解释评分、点击卡片完成预约、查询本人待开始预约。
- 浏览器助手页面：四项分数来源、条件更新、纯文本防止回复HTML执行、预约和取消需确认、网络失败保持同cardId、过期按钮、错误保留上一轮、未配置降级及390px手机布局。助手接口在此层使用模拟响应，实际工具和数据库已由上一层分别验证。
- 浏览器原流程：学生注册／登录／预约／取消／推荐／退出，管理员自习室与座位维护、预约记录和统计，未发现页面JavaScript错误。

## 性能记录

Windows 11、Java 21.0.5、MySQL 8.0.41、Intel Core i7-13620H，16个逻辑处理器，JVM最大堆约3.95GiB。创建10,000条性能预约，其中8,000条有效历史；测量时库内10,001条预约、5个自习室、75个座位，含既有及逻辑删除资源。

单客户端，每接口预热10次后连续100次请求，升序第95个值为P95。采用MockMvc完整服务端分发，包含安全、数据库及序列化，排除网络与浏览器渲染。测量时间2026-10-30 21:03:49（北京时间）。

|接口|P95（毫秒）|标准|
|---|---:|---|
|GET /room/list|22.39|≤1000|
|GET /seat/list/{roomId}|51.12|≤1000|
|GET /reserve/myList|20.04|≤1000|
|GET /ai/recommend|124.21|≤1000|
|GET /admin/reserve/list|26.88|≤1000|
|GET /admin/statistics/daily|1.70|≤1000|

原查询接口达到本地验收目标。DeepSeek聊天依赖公网和上游生成，不适用原业务接口P95≤1秒的指标；每轮最大60秒保护已通过模拟超时与本地HTTP测试验证。没有向真实上游制造限流或故意使用无效密钥，429及凭据错误通过本地HTTP测试验证。

## 边界与交付

模型自然语言理解有不确定性，不能保证所有表达都正确识别。上限触发时丢弃草稿，保留上一轮结果；模型说明与卡片不一致时以服务端卡片为准，只有按钮才能提交预约或取消。

当前仅支持本机单实例Session及内存额度，重启不恢复；没有长期偏好、RAG、流式输出、多实例同步或自动写操作。基础预约仍不能确认实际到场。前端主包约959kB（gzip约317kB），构建存在体积提示，后续可按组件或路由拆分。

未进行浏览器静置30分钟的会话耐久测试，Session失效采用解绑与销毁场景覆盖；未进行高并发吞吐量或长时间公网稳定性测试。截图位于忽略的.cache，配置、密钥及测试日志未纳入Git。版本文件同步为1.1.0，本次没有执行Git提交、版本标签或推送。
