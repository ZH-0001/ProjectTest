## 性能环境与口径

- Windows 11；Intel Core i7-13620H，16个逻辑处理器；物理内存约15.8GiB。
- Java 21.0.5；MySQL 8.0.41；JVM最大堆约3.95GiB；后端单实例。
- 生成10,000条测试预约，其中8,000条为有效历史。测试时库内共10,001条预约、5个自习室、75个座位；资源计数包含逻辑删除记录。新增性能数据属于1个测试自习室、2个座位。
- 每个接口预热10次后，由单客户端连续请求100次，耗时升序排列后的第95个值为P95。
- 通过Spring MockMvc执行完整服务端请求分发、安全过滤、数据库查询及JSON序列化；不包含真实Socket传输、浏览器渲染和互联网延迟。

## 交付边界

基础版记录预约，不验证实际到场；没有签到、信用积分、Redis、大模型或校园统一身份认证。推荐为本地历史偏好规则算法，沿用 `/ai/recommend` 接口路径。

单次统计日期范围最多367天，可分段查询。这是实现层的资源保护限制。自习室级事务锁会让同室写入串行，适用于当前单实例教学项目；前端构建成功，但完整引入Element Plus使主JS包约950kB（gzip约314kB），后续可按组件导入和拆分路由改善首次加载。

浏览器测试会在专用测试库保留随机学生、已取消预约和逻辑删除的测试空间。测试截图仅保存在被Git忽略的 `.cache/` 中；配置和凭据不纳入Git。开发库中的人工预览预约已取消，保留取消历史。

## 复验命令

先按根目录 `README.md` 配置本机数据库与管理员密码。后端测试与浏览器测试依次执行：

```powershell
mvn -B -f backend/pom.xml test
cd frontend
npm run test:e2e
```

后端测试源文件位于 `backend/src/test/java/cn/edu/studyroom/`，浏览器测试及专用服务配置位于 `frontend/tests/`、`frontend/playwright.config.js` 和 `scripts/start-test-backend.ps1`。
